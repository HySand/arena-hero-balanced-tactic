# 战术算法与取舍

本文说明当前自动战术真正采用的决策原则，也记录外部方案中没有照搬的部分。所有行为以当前 `Turn`、Arena Hero 规则 v0.14 和官方 Python SDK 为准。

## 统一执行边界

权威决策入口是 `arena_hero_tactic/strategy_core/planner.py` 的 `plan_tick(state, memory, config)`。本地官方 SDK 路径只负责把 `Turn` 转成规范状态并应用返回的 `CommandPlan`；Cloudflare TypeScript Worker 只负责 WebSocket、状态、严格解码、计划校验和命令提交，策略计算由 Python Durable Object 调用同一 Python 核完成。

迁移观察期内，TypeScript planner 只保留为管理员显式选择的 `typescript_primary` 回滚路径。`python_shadow` 不提交 Python 计划；`python_primary` 失败时只运行最小安全计划，不能自动调用完整 TypeScript planner。

## 决策顺序

每个 Tick 重新读取完整权威状态，再按以下优先级规划：

1. 缺失 Core 或兼容性保护状态下不构造虚假动作。
2. Core、受伤单位和受威胁 Worker 的即时生存。
3. 当前可执行的攻击、追击、撤退和堵路。
4. 已分配的敌方跟踪任务。
5. Worker 的采集、返航、交付和满仓探索。
6. 地图前沿、资源区和陈旧视野复查。
7. 安全状态下的固定环防与普通巡逻。
8. Core 的恢复、生产、迁移和 Beacon 决策。

Manual 与 Agent 的动作优先级由服务器按对象合并：Manual 显式动作优先于 Agent。战术不再实现一套可能与服务器冲突的本地“手动覆盖层”。

## 寻路与移动

- 使用已确认可通行格上的 BFS，并按起点缓存整张距离图。
- 未知格可以作为探索终点，但不能作为穿越障碍记忆的中间捷径。
- 全局资源分配需要从一个起点同时比较多个目标，BFS 距离图比逐目标 A* 更合适。
- 移动规划会记录本 Tick 已确定的离开和进入位置，遵守每格最多两个实体的容量。
- 近期位置用于惩罚 A-B-A 往返；稳定目标只有在失效、到达或高优先级危险出现时才替换。
- 障碍、敌方占位、己方预约和危险评分都会影响下一步，但最终动作仍只提交合法的四向移动。

## Worker 与资源

资源不是按“每个 Worker 找最近点”分配，而是做全局匹配。成本包含：

- Worker 到资源的真实路线；
- 资源返回 Core 的路线；
- 整个往返是否超过有效采集半径；
- 当前危险、陈旧资源记忆和目标粘性；
- 其他 Worker 已占用的资源点；
- Core 剩余容量和迁移状态。

满载 Worker 优先交付。Core 已满时不重复无效提交，而是安全探索；Core 迁移期间等待或离开入口，迁移结束后恢复交付。资源点在当前视野中明确消失后立即失效，不能把历史资源记忆当作实时资源。

## 地图与探索

- 当前视野回答“现在有什么”，历史地图只回答“过去知道什么”。
- 障碍永久记忆；资源、敌人和占位根据新 Turn 重新验证。
- Worker 和战斗单位使用持久分区、前沿信息增益和陈旧视野复查，避免所有单位沿同一射线探索。
- 不把雾区中看似封闭的区域永久标记为不可达。当前地图并不完整，而且规则保证生成的可通行区域连接；永久剪枝容易误删后来发现的入口。

## 敌方记忆与预测

可见敌人会保存当前位置、上一位置、生命值、类型和最后目击 Tick。敌人离开视野不等于死亡：

- 轨迹在有限搜索窗口内保留；
- 根据最后一个合法四向位移估计主要方向；
- 游侠只在当前尚未覆盖的可能位置中选择预测射击点；
- 先锋或未被环防绑定的单位会选择能覆盖最多盲区的可达搜索点；
- 搜索点同时考虑预测方向、路线长度、视野遮挡和访问次数；
- 搜索区域被覆盖、超时或目标重新出现后，单位恢复正常职责。

对可见目标，游侠仍会在当前位置、预测下一位置和邻格之间分散火力。目标格必须通过现行水平、垂直或精确对角射击校验。

## 战斗与 Core 防御

- Core 通常是高价值目标，但己方 Core 附近的即时攻击威胁优先。
- 两名 Ranger 保留稳定的 Core 环防扇区；出现近距离威胁时才离开巡逻环。
- 远处敌人可由其他战斗单位跟踪，少量健康、空载 Worker 只在严格距离和容量条件下承担堵路。
- 受伤单位优先回到静止 Core 并使用 `HEAL`；Core 先恢复 HP，再按姿态决定护盾、紧急生产、普通生产或迁移。
- 不采用固定的 15/2/2 或其他永久兵力配方。生产使用动态单位成本、当前威胁、资源储备、人口和可配置目标。

## 稳定性与持久化

地图、资源提示、敌方轨迹、巡逻扇区和必要目标会跨 Tick 保存。状态采用临时文件后原子替换，配置支持运行时热加载。单实例锁、版本保护和官方 SDK 重连负责长期运行稳定性。

## 明确没有采用

以下想法没有直接加入主策略：

- 每个目标单独运行 A*：不适合当前一对多距离比较和全局资源匹配。
- 永久“不可探索区域”剪枝：雾区信息不完整，容易把未知入口误判为不存在。
- 随机抖动、模拟退火或人工势场：会降低确定性，并消耗有限规划时间。
- 未校准的机器学习攻击模型：目前没有可靠伤害和命中样本支撑。
- 只看局部距离的贪心移动：已有 BFS、预约和全局目标评分。
- 固定兵力模板：忽略动态成本、维护费、战损和实时威胁。
- 对本 Tick 已确认空白的最后目击格盲射：只保留当前仍未覆盖的合法预测点。
